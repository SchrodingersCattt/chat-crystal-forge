CrystalForge app map

An offline, source-grounded reference route for the CrystalForge preparation workflow. This map describes the code at commit 5d1fe90; it is not a claim that every route has been exercised by a learner.

What the app does

CrystalForge registers immutable CIF copies, asks MolCrysKit for inspection evidence, records explicit hydrogen and disorder decisions, reloads exports for the same checks, and lets code—not model prose—decide whether /finish can pass. MatterVis supplies the native viewer in the browser UI and terminal UI; one ForgeService supplies the workflow state to both.

One action from input to visible result

Reference route (2–3 stops)

  1. Start the host. src/chat_crystal_forge/cli.py defines ui() and tui(). Both call create_service(), register a copied CIF, and pass the same service into MatterVis through ForgeChatExtension.
  2. Follow a command. In src/chat_crystal_forge/plugins.py, the web callback submit() and TUI handler on_input_submitted() forward text to ForgeService.submit(). In src/chat_crystal_forge/service.py, _direct() validates slash commands and _tool() calls inspect_file(), preparation jobs, export reloads, or finish().
  3. Read the evidence. ForgeService.snapshot() reads messages, structures, revisions, jobs, decisions, and exports from session.sqlite3. The extension's refresh() renders those records as chat cards and status text; it does not decide scientific outcomes.

To change this, start here

  • Change command parsing or usage text: src/chat_crystal_forge/service.py, _direct() and _direct_result().
  • Change preparation or completion policy: src/chat_crystal_forge/service.py, complete_hydrogens(), resolve_disorder(), export_structure(), and finish(); keep policy shared by both frontends.
  • Change panel layout or presentation: src/chat_crystal_forge/plugins.py, build_web_panel(), build_tui_panel(), and refresh(). Viewer behavior belongs in the MatterVis checkout.
  • Change the session HTTP surface: src/chat_crystal_forge/http.py, create_app(). API responses intentionally omit local file paths.

A practice to reuse

Make the acceptance condition observable before wiring a workflow. Here, tests/test_preparation_workflow.py exercises ambiguous hydrogen decisions, bounded disorder output, and restart recovery, while ForgeService.finish() checks actual reloaded exports and hashes. On another project, write the visible pass/fail evidence and its test or storage location first; then keep UI code responsible for showing that evidence rather than inventing a success message.

Run it again

From an activated Python 3.11+ environment with the pinned submodules installed:

python -m pip install -e external/molcryskit -e "external/mattervis[all,test]" -e ".[dev]"
mat-chat ui examples/structures/DAP-4.cif --session .crystalforge/dap4-demo
mat-chat tui --session .crystalforge/dap4-demo
python -B -m pytest tests
ruff check src tests

Use the runnable demo for the complete slash-command sequence. A live natural-language request additionally needs local OPENAI_API_KEY, OPENAI_BASE_URL, and OPENAI_MODEL; never put those values in this map.
